# Code of Conduct

Sable is a place to build, learn, and ship together. Everyone — first-time contributors, seasoned maintainers, designers, writers, lurkers — should feel safe participating. This document explains what that looks like in practice.

## How we work

- **Assume good intent.** People come from different backgrounds, time zones, and experience levels. A short or oddly-phrased message usually isn't hostility.
- **Be specific, be kind.** Critique code, not people. "This loop will allocate every keystroke" beats "this is bad".
- **Welcome questions.** Beginner questions are how a project keeps growing. If you've answered the same one three times, write a doc and link it.
- **Credit work.** When you build on someone's PR, idea, or bug report, say so.
- **Disagree, then commit.** Honest dissent is encouraged. Once a maintainer makes a call, move forward — even if you'd have chosen differently.
- **Default to public.** Decisions in DMs are decisions nobody else can learn from. Bring discussions to issues / PRs whenever you can.

## What's not OK

- Personal attacks, harassment, or insults — including jokes "at someone's expense".
- Sexual or violent content in issues, PRs, commits, or chat.
- Sharing someone's private information without their consent.
- Discrimination based on race, gender, sexuality, religion, nationality, disability, age, body size, or any similar attribute.
- Sustained derailment or trolling.
- Repeatedly ignoring a maintainer's request to drop a thread.

## Reporting

If you see or experience behaviour that feels off — even if you're not sure it crosses a line — please email **conduct@sable.dev** (replace with the real address before launch). All reports are read by maintainers, kept confidential, and answered within seven days.

You can also report someone privately via GitHub: open a private security advisory addressed to the maintainers. We'll route it.

## What happens after a report

Maintainers investigate, talk to the people involved, and choose a response proportional to the situation. Possible outcomes:

1. A private clarification or apology.
2. A public clarification of expectations on the relevant issue / PR.
3. A temporary or permanent ban from project spaces (issues, PRs, releases, chat).

We err toward warning + mediation for first-time issues and toward firmer consequences for repeated patterns or anything explicitly in the "What's not OK" list.

## Scope

This applies inside every Sable space — the GitHub repo, issues, PRs, releases, official chat channels, project events — and to behaviour outside Sable when it spills back in (for instance, harassing a maintainer on another platform).

## Maintainer responsibilities

Maintainers enforce this consistently. If a maintainer's own behaviour is the problem, escalate to another maintainer; if that's not workable, escalate via email above.

---

This Code of Conduct is short on purpose. Treat it as the floor, not the ceiling. The goal is a project where everyone trusts they'll be treated decently — and we'll keep refining this document as we learn what helps.
